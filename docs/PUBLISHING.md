# GitHub publication checklist

The repository has no Git remote configured. Complete these gates before the first
public push.

## Rights and provenance

The owner confirmed that the previously separate Football Core is their code. Its
accepted runtime source is now included under `services/perception` and licensed
with the rest of the owner's project under Apache-2.0. Its source provenance is
machine-verifiable with `scripts/verify_perception_source.py`.

Vendored third-party notices/licenses must remain intact. This repository license
does not relicense model weights, datasets or match footage.

SoccerNet archives, match footage, model checkpoints and generated runs must remain
outside Git. Their paths are ignored and the publication checker rejects common
artifact extensions.

The optional `.build/football-intelligence-weights-*.tar` is a local/private release
artifact, not part of the source release. Do not attach it to a public GitHub release
until redistribution rights for every entry in `configs/weights-manifest.json` have
been reviewed independently.

## Local release gate

Run from a fresh terminal at the repository root:

```powershell
python scripts/check_public_repository.py
python scripts/verify_perception_source.py
python -m ruff check .
python -m pytest
python -m pip wheel . --no-deps --wheel-dir .build/wheels
docker compose config --quiet
docker compose --profile full config --quiet
.\scripts\quickstart.ps1
Invoke-RestMethod http://127.0.0.1:8080/api/v1/health
docker compose down
```

The expected CPU/UI clean-clone health state has API status `ok`, perception
`not_configured` and semantic VLM disabled. Full GPU startup additionally requires
CUDA and external checkpoints, but no second source repository or base image.

Review `git status` and the staged diff before committing. In particular, verify
that `.env`, `weights/`, `data/runtime/`, `data/soccernet/`, `runs/*`, video files
and `.build/` are absent.

## Create and push

Create an empty GitHub repository without an autogenerated README/license, then use
the URL GitHub displays:

```bash
git remote add origin <github-repository-url>
git add --all
git diff --cached --check
git status --short
git commit -m "Prepare reproducible public release"
git push -u origin HEAD
```

No automated command in this project creates a remote repository or pushes data.
That keeps the final public visibility and rights decision with the owner.

After pushing, require the CI workflow for pull requests and enable GitHub secret
scanning, private vulnerability reporting and Dependabot alerts. Add a release tag
only after CI succeeds. Suggested topics: `football-analytics`, `computer-vision`,
`video-analysis`, `soccer`, `vlm`.
