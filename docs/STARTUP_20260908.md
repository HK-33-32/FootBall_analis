# Startup cost experiment — 8 September 2026

## Scope and reference

Continuation of docs/PERFORMANCE_20260908.md. The previous native ARG–FRA job
records concurrent calibration 38.8 s and tracking 109.2 s, so tracking was its
critical path. Existing in-loop counters accounted for only 21.2 s; they did not
separately identify import/model initialization costs.

Use the same 7.6 s, 190-frame development video, 1080p/25 FPS, RF-DETR large,
batch size 8 and jersey stride 3. No validation/frozen annotations are involved.
The isolated startup harness regenerates frames using the production extraction
settings, runs the actual GSRPipeline, and retains tracking CSVs plus their hashes.
It does not rerun calibration, IDATR, semantic statistics or a full match.

## One-factor change

Increase RF-DETR's MD5 read size from 4 KiB to 1 MiB. Still read the entire file
on every check; do not memoize hashes, trust timestamps, disable verification or
change the expected digest. No model, precision, frame sampling, threshold, ReID
diagnostic or network-check behavior changes.

Configuration: configs/core_io.json. The installed upstream function is extracted
for a real-file component A/B by scripts/benchmark_weight_io.py. The resulting
source-checked patch is exported only after equality and speed acceptance.

## Reproduction tools

~~~powershell
python -m pytest tests/unit/test_core_startup.py tests/unit/test_weight_io.py tests/unit/test_core_overlay.py
docker build -f docker/Dockerfile.startup -t football-core:startup-20260908 .
python scripts/run_core_startup.py --name new-baseline --image football-core:performance-20260908
# Wait for completion before launching the candidate, to avoid GPU/I/O interference:
docker wait fi-startup-new-baseline
python scripts/run_core_startup.py --name new-candidate --image football-core:startup-20260908
docker wait fi-startup-new-candidate
python scripts/compare_core_startup.py --baseline data/runtime/startup_20260908/baseline1/manifest.json --candidate data/runtime/startup_20260908/candidate1/manifest.json --output data/runtime/startup_20260908/pair1.json
~~~

The host launcher checks local inputs/caches, resolves and runs the immutable image
ID with pulling/network disabled, and saves the exact command under launches/.
Use unique names/output files; the comparison example refers to the measured runs.
The container harness requires the same cached CLIP/torch/RF-DETR mounts as the
earlier performance protocol. Its CLI requires video, effective config, source
manifest, immutable image ID and a new output directory; it refuses to overwrite
an experiment. Failed/incomplete runs are never accepted by the comparator.
